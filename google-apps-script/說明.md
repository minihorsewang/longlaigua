# 訂單寫入 Google 試算表：設定步驟

客人在網站按「送出訂單」→ 訂單自動新增到你的 Google 試算表「訂單」工作表。

## 一、建立試算表並貼上程式（約 5 分鐘）

1. 到 [Google 試算表](https://sheets.google.com) 建立一份**空白試算表**，命名例如「龍來刮訂單」
2. 上方選單「**擴充功能**」→「**Apps Script**」
3. 把編輯器裡原本的內容全部刪掉，貼上 `Code.gs` 的全部內容 → 按 💾 儲存
4. 上方函式選單選 **`setup`** → 按「**執行**」
   - 第一次會跳出授權：選你的 Google 帳號 →「進階」→「前往（不安全）」→「允許」
   - 這是因為程式是你自己寫的、還沒經過 Google 審核，屬正常現象
5. 回到試算表，會看到兩個新工作表：「**訂單**」「**商品**」

## 二、部署成網址

1. Apps Script 右上角「**部署**」→「**新增部署作業**」
2. 左邊齒輪 ⚙️ 選「**網頁應用程式**」
3. 設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**（客人沒有你的帳號也要能下單）
4. 按「部署」→ 複製「**網頁應用程式網址**」（`https://script.google.com/macros/s/.../exec`）
5. 用瀏覽器打開這個網址，看到 `"ok":true` 就代表成功

## 三、接到網站

打開網站的 `app.js`，最上方：

```js
const ORDER_API_URL = '';
```

把網址貼進引號中間，存檔即可。

## 日常使用

| 要做的事 | 怎麼做 |
|---|---|
| 看新訂單 | 打開試算表「訂單」工作表 |
| 標記出貨 | 改「狀態」欄（例如 待出貨 → 已上傳 → 已出貨） |
| 改價格／下架商品 | 改「商品」工作表的價格，或取消勾選「上架」 |
| 匯出給 7-11 | 篩選「待出貨」→ 複製到 7-11 範例檔；或「檔案」→「下載」→ CSV |

> ⚠️ 改價格時，網站 `app.js` 的 `PRODUCTS` 也要一起改。客人在網站上看到的是 `app.js` 的價格，實際收的是試算表的價格。

## 修改程式後要重新部署

改了 `Code.gs` 之後，要「部署」→「**管理部署作業**」→ ✏️ 編輯 → 版本選「**新版本**」→ 部署。
這樣網址不會變，網站不用改。（如果按「新增部署作業」會產生新網址。）

## 每月消費排名（2026-10-16 新增，第 8 版）

只有網站會員參加；蝦皮、賣貨便的客人也要先加入會員（蝦皮客人要在會員中心綁定蝦皮帳號）。

每月初的步驟（2026-10-16 第 9 版起改為從雲端硬碟匯入）：

1. 把最新的出貨檔 Excel 上傳到刮刮帳號 Google 雲端硬碟的「**龍來刮出貨檔**」資料夾（setup 自動建立）。可以直接覆蓋舊檔，或放新檔；程式會用**最近修改**的那個檔案
2. 打開試算表，上方選單「龍來刮」→「匯入出貨檔並計算上個月排名」（或「…指定月份排名…」輸入 `2026-07`）
   - 程式會讀 Excel 的「客戶名單」工作表，整張覆蓋到試算表「出貨檔」，再計算；轉檔用的暫存檔用完會自動丟到垃圾桶
   - 只想看匯入結果：「只匯入出貨檔（不計算）」
3. 看「每月排行」（名次、會員、各來源金額）和「排行明細」（每筆訂單對應到誰；「無法確定」「未綁定」的可人工確認）
4. 確認無誤後，在「每月排行」該月份的「公布」欄打勾 → 網站「中獎」頁和首頁公告就會顯示（姓名遮罩，只公布前 10 名、最近 12 個月）

- 這個功能用到 Apps Script「服務」裡的 **Drive API**（已加入），以及雲端硬碟權限（2026-10-16 已重新授權）
- 資料夾名稱、工作表名稱在 `Code.gs` 的 `SHIPMENT_FOLDER`、`SHIPMENT_SOURCE_SHEET`

計算規則：

- 金額＝售價合計（不含運費、優惠券折抵前）；網站訂單用「商品小計」，狀態含取消／退貨／退款／測試的不算
- 網站：依訂單「會員編號」；蝦皮：買家 ID＝會員綁定的蝦皮帳號（不分大小寫）；賣貨便：手機前 4 碼＋末 3 碼＋姓氏比對會員，多人符合時標「無法確定」不計入
- ID 是商品文字（例如「龍蛋*10張」）的列略過；退貨工作表暫不處理
- 同月份可重複計算（會覆蓋該月結果），但已勾「公布」的月份會被鎖定，要重算請先取消勾選

## 上架商品（2026-10-13 起只要改試算表）

「商品」工作表一列＝一個商品，網站開啟時自動讀取（客人重新整理就看得到）：

| 欄 | 欄位 | 怎麼填 |
|---|---|---|
| A | 商品ID | **必填、不能重複**，例如 `p14`；只能用英文、數字、`-`、`_`；上架後不要再改（購物車和訂單靠它對應） |
| B | 名稱 | 必填 |
| C | 價格 | 必填，大於 0；網站顯示和實際收款都用這個 |
| D | 上架 | 打勾＝網站顯示；取消勾選＝下架 |
| E | 分類 | 下拉選：刮刮卡／禮盒組合／周邊小物；空白＝只出現在「全部商品」 |
| F | 角標 | 選填，例如 熱銷、新品、限量、9 折 |
| G | 熱銷 | 打勾＝出現在首頁「熱銷商品」 |
| H | 圖示 | 選填，沒照片時顯示的 emoji；空白＝用分類圖示 |
| I | 照片網址 | 選填。Google 雲端硬碟：檔案按「共用」→「知道連結的任何人」→ 複製連結貼上即可；其他網址需 https 開頭。照片讀不到時自動顯示圖示 |
| J | 說明 | 選填（目前網站尚未顯示，預留） |

- 第 1 列欄名不要改；新增的分類要同時改網站 `app.js` 的 `CATEGORIES`
- 網站會記住上次讀到的商品，客人開站時先顯示舊的，約 1～3 秒後換成最新的
- 頻道目前是 **Developing**：只有頻道管理員能登入。測試沒問題後，到 LINE 後台把狀態改成 **Published**

## 出貨抽獎

1. 在原 Apps Script 專案更新 Code.gs，新增 HTML 檔 ShipmentQr 與 ShipmentQrLibrary，分別貼入同名檔案內容。更新原網頁應用程式部署到新版本，沿用原網址。
2. 重新整理試算表，選「龍來刮 → 初始化出貨抽獎工作表」。建立「出貨抽獎與領獎」及「出貨獎項」。
3. 在「出貨獎項」A～C 欄輸入獎品名稱、整數權重、啟用。測試可先只填「測試刮刮卡一張」、1、是。正式開放前填正式獎品與權重；權重比例即抽取機率，第一版每次抽到一項，沒有庫存扣減。
4. 選「龍來刮 → 產生或重印出貨抽獎連結」，輸入唯一出貨單號（例如 TEST-001），列印 QR Code。相同單號重印會取回原碼。首次掃碼且按抽獎的 LINE 帳號會持有該獎品，出貨時應將碼放入正確包裹。
5. 用未註冊的 LINE 帳號掃碼、抽獎，關閉後重掃，應顯示原獎品。完成會員註冊後確認領獎，後台同一列 G～J 欄應有領獎單號、會員編號、領獎時間與「待處理」。重掃及重送不會再建一筆。換另一個 LINE 帳號重掃應無法領取。
6. 出貨人員依領獎列處理獎品，於 J 欄改填處理狀態。測試單用 TEST 前綴，避免誤出貨。
